# Migrating from v1.0 to v1.1

**Target Version:** v1.1.0  
**Source Version:** v1.0.x (last: v1.0.4)  
**Estimated Effort:** 2-4 hours  
**Risk Level:** Low  
**Release Date:** 2026-05-15

---

## Summary of Changes

Version 1.1 introduces tenant-scoped API keys, structured logging, and the contract dashboard. The authentication flow has been refactored to support the 8-phase middleware pipeline (ADR-029), and several endpoints have moved from `api/v1/` to `api/v1/admin/` for administrative operations.

### New Endpoints

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/api/v1/admin/tenants` | `GET` | List all tenants (admin only) |
| `/api/v1/admin/contracts` | `GET` | View contract compliance dashboard |
| `/api/v1/admin/contracts/:id/validate` | `POST` | Validate contract against implementation |
| `/api/v1/tenants/:id/api-keys` | `POST` | Create scoped API key for tenant |
| `/api/v1/tenants/:id/api-keys/:keyId` | `DELETE` | Revoke API key |
| `/api/v1/health/detailed` | `GET` | Detailed health check with dependency status |

### Modified Endpoints

| Endpoint | Change | Details |
|----------|--------|---------|
| `/api/v1/tenants` | `POST` body changed | Now accepts `admin_email` field; `tier` is required |
| `/api/v1/ingestion/documents` | Query params added | Supports `?processing_mode=sync\|async` (default: `async`) |
| `/api/v1/workflows/run` | Response shape changed | Now returns `workflow_id`, `status`, `estimated_completion` |

### Deprecated Endpoints

| Endpoint | Replacement | Removal Target |
|----------|-------------|----------------|
| `/api/v1/health` (simple) | `/api/v1/health/detailed` | v1.3.0 |
| `X-Tenant-ID` header | `Authorization: Bearer <tenant-scoped-key>` | v2.0.0 |

## Breaking Changes

### BC-1: Authentication Header Required

**Before (v1.0):**
```bash
# Tenant ID passed via header, no auth required for read endpoints
curl http://localhost:8001/api/v1/tenants \
  -H "X-Tenant-ID: tenant-123"
```

**After (v1.1):**
```bash
# All endpoints require Bearer token with tenant-scoped API key
curl http://localhost:8001/api/v1/tenants \
  -H "Authorization: Bearer fab_ak_abc123xyz789"
```

**Migration:**
1. Generate API keys for existing tenants:
   ```bash
   # Run migration script (included in v1.1 release)
   python scripts/migrations/v1.0-to-v1.1/generate-api-keys.py
   ```
2. Update all client code to use `Authorization: Bearer` header
3. Remove `X-Tenant-ID` header usage

### BC-2: Workflow Response Shape

**Before (v1.0):**
```json
{
  "id": "wf_abc123",
  "state": "running",
  "created_at": "2026-05-15T10:30:00Z"
}
```

**After (v1.1):**
```json
{
  "workflow_id": "wf_abc123",
  "status": "running",
  "estimated_completion": "2026-05-15T10:35:00Z",
  "created_at": "2026-05-15T10:30:00Z",
  "_links": {
    "self": "/api/v1/workflows/wf_abc123",
    "results": "/api/v1/workflows/wf_abc123/results"
  }
}
```

**Migration:**
1. Update response parsing to use `workflow_id` instead of `id`
2. Update response parsing to use `status` instead of `state`
3. Use `_links.self` for status polling instead of constructing URLs

### BC-3: Database Migration Required

A database migration adds the `api_keys` table and modifies the `tenants` table.

```bash
# Automatic migration on startup (when AUTO_MIGRATE=true)
docker compose up -d

# Or manual migration
make migrate
```

## Step-by-Step Migration Checklist

### Pre-Migration (15 minutes)

- [ ] **Backup database** — `pg_dump fabric4l > fabric4l-v1.0-backup.sql`
- [ ] **Backup configuration** — `cp .env .env.v1.0-backup`
- [ ] **Review custom integrations** — Identify all API clients using `X-Tenant-ID`
- [ ] **Check deprecated endpoint usage** — Search for `/api/v1/health` without `/detailed`
- [ ] **Schedule maintenance window** — Migration requires ~5 minutes downtime

### Migration (30 minutes)

- [ ] **Pull v1.1 code** — `git fetch origin && git checkout v1.1.0`
- [ ] **Review release notes** — `cat RELEASE_NOTES_v1.1.0.md`
- [ ] **Update environment variables** — Add new required variables (see below)
- [ ] **Run database migrations** — `make migrate`
- [ ] **Generate tenant API keys** — `python scripts/migrations/v1.0-to-v1.1/generate-api-keys.py`
- [ ] **Deploy services** — `docker compose -f infra/compose/docker-compose.prod.yml up -d`
- [ ] **Verify health** — `curl http://localhost:8001/api/v1/health/detailed`

### Post-Migration (1-2 hours)

- [ ] **Update API clients** — Replace `X-Tenant-ID` with `Authorization: Bearer`
- [ ] **Update workflow response handling** — Migrate to new response shape
- [ ] **Test all integrations** — Run integration test suite
- [ ] **Verify structured logging** — Check `logs/structured/` for JSON log output
- [ ] **Review contract dashboard** — Navigate to `/api/v1/admin/contracts`
- [ ] **Monitor for 24 hours** — Watch error rates and latency dashboards

### Validation

```bash
# Verify API key authentication works
curl http://localhost:8001/api/v1/tenants \
  -H "Authorization: Bearer $API_KEY" \
  | jq '.[0].id'

# Verify workflow response shape
curl -X POST http://localhost:8004/api/v1/workflows/run \
  -H "Authorization: Bearer $API_KEY" \
  -d '{"workflow_type": "insight_generation", "inputs": {"query": "test"}}' \
  | jq '{ workflow_id, status, estimated_completion }'

# Verify health endpoint
curl http://localhost:8001/api/v1/health/detailed | jq '.status'
```

### New Variables (Required)

| Variable | Default | Description |
|----------|---------|-------------|
| `API_KEY_ENCRYPTION_KEY` | — | 32-byte key for encrypting API keys at rest |
| `LOG_FORMAT` | `json` | Log format: `json` or `text` |

### New Variables (Optional)

| Variable | Default | Description |
|----------|---------|-------------|
| `AUTO_MIGRATE` | `false` | Run migrations on startup |
| `CONTRACT_VALIDATION_ENABLED` | `true` | Enable contract validation on admin endpoints |

| Variable | Replacement | Removal Target |
|----------|-------------|----------------|
| `TENANT_ID_HEADER` | `Authorization` header | v2.0.0 |
| `SIMPLE_HEALTH_ENDPOINT` | `ENABLE_DETAILED_HEALTH=true` | v1.3.0 |

## Code Examples

### Python SDK Migration

**Before (v1.0):**
```python
from fabric4l import FabricClient

client = FabricClient(
    base_url="http://localhost:8001",
    tenant_id="tenant-123",  # Deprecated
)

# Run workflow
result = client.workflows.run(
    workflow_type="insight_generation",
    inputs={"query": "What are the key themes?"}
)
print(result["id"])  # Deprecated field name
```

**After (v1.1):**
```python
from fabric4l import FabricClient

client = FabricClient(
    base_url="http://localhost:8001",
    api_key="fab_ak_abc123xyz789",  # New: tenant-scoped API key
)

# Run workflow
result = client.workflows.run(
    workflow_type="insight_generation",
    inputs={"query": "What are the key themes?"}
)
print(result["workflow_id"])  # New field name
print(result["estimated_completion"])  # New field
```

### JavaScript/TypeScript SDK Migration

**Before (v1.0):**
```typescript
import { FabricClient } from '@fabric4l/sdk';

const client = new FabricClient({
  baseURL: 'http://localhost:8001',
  tenantId: 'tenant-123', // Deprecated

// Run workflow
const result = await client.workflows.run({
  workflowType: 'insight_generation',
  inputs: { query: 'What are the key themes?' },

console.log(result.id); // Deprecated field
```

**After (v1.1):**
```typescript
import { FabricClient } from '@fabric4l/sdk';

const client = new FabricClient({
  baseURL: 'http://localhost:8001',
  apiKey: 'fab_ak_abc123xyz789', // New: tenant-scoped API key
});

// Run workflow
const result = await client.workflows.run({
  workflowType: 'insight_generation',
  inputs: { query: 'What are the key themes?' },
});
console.log(result.workflowId); // New field name
console.log(result.estimatedCompletion); // New field
```

### cURL Examples

**Before (v1.0):**
```bash
# Create tenant
curl -X POST http://localhost:8001/api/v1/tenants \
  -H "Content-Type: application/json" \
  -d '{"name": "My Tenant", "tier": "shared"}'

# Upload document
curl -X POST http://localhost:8001/api/v1/ingestion/documents \
  -H "X-Tenant-ID: tenant-123" \
  -F "file=@document.pdf"
```

**After (v1.1):**
```bash
# Create tenant (now requires admin_email)
curl -X POST http://localhost:8001/api/v1/tenants \
  -H "Content-Type: application/json" \
  -d '{"name": "My Tenant", "tier": "shared", "admin_email": "admin@example.com"}'

# Generate API key for tenant
curl -X POST http://localhost:8001/api/v1/tenants/tenant-123/api-keys \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name": "Production Key", "scopes": ["read", "write"]}'

# Upload document (now uses Bearer auth)
curl -X POST http://localhost:8001/api/v1/ingestion/documents \
  -H "Authorization: Bearer fab_ak_abc123xyz789" \
  -F "file=@document.pdf"
```

## Rollback Procedure

If migration fails, rollback to v1.0:

```bash
# 1. Stop services
docker compose down

# 2. Restore database
psql fabric4l < fabric4l-v1.0-backup.sql

# 3. Restore configuration
cp .env.v1.0-backup .env

# 4. Checkout v1.0 code
git checkout v1.0.4

# 5. Start services
docker compose -f infra/compose/docker-compose.prod.yml up -d

# 6. Verify rollback
curl http://localhost:8001/api/v1/health | jq '.status'
```

## Troubleshooting

### "Invalid API key format" error

**Cause:** API key doesn't match the new `fab_ak_` prefix format.  
**Fix:** Regenerate API keys using the migration script:
```bash
python scripts/migrations/v1.0-to-v1.1/generate-api-keys.py
```

### "X-Tenant-ID header is deprecated" warning

**Cause:** Client code still sends `X-Tenant-ID`.  
**Fix:** Update client to use `Authorization: Bearer <api-key>` header.

### Database migration fails

**Cause:** Migration may conflict with custom schema changes.  
**Fix:**
1. Check migration logs: `docker logs fabric4l-api | grep migration`
2. Run migrations manually with verbose output: `alembic upgrade head -v`
3. If conflict exists, contact support with migration log output

### Missing `admin_email` field

**Cause:** Tenant creation now requires `admin_email`.  
**Fix:** Add `admin_email` to all tenant creation requests.

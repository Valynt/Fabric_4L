# Migrating from v1.1 to v1.2

**Target Version:** v1.2.0  
**Source Version:** v1.1.x (last: v1.1.8)  
**Estimated Effort:** 3-6 hours  
**Risk Level:** Medium  
**Release Date:** 2026-07-14

---

## Summary of Changes

Version 1.2 is a major feature release ratifying 6 architecture contracts, introducing the feature flag system, GDPR compliance endpoints, Scalar API documentation, and official SDKs. This release also removes several long-deprecated endpoints and fields.

### Highlights

- **6 Architecture Contracts Ratified** — All active ADRs (ADR-028, ADR-029, ADR-033, ADR-031, and ADR-032) plus ADR-021 now have contract validation
- **Feature Flag System** — LaunchDarkly-compatible feature flag API with kill switches
- **GDPR Compliance** — Full data deletion and export endpoints for regulatory compliance
- **Scalar API Documentation** — Interactive API docs replacing static OpenAPI renderers
- **Official SDKs** — Python and TypeScript SDKs with full type coverage
- **OTel Tracing** — OpenTelemetry distributed tracing across all 6 layers
- **Chaos Engineering** — Built-in fault injection and resilience testing

## Removed Endpoints (Breaking)

| Endpoint | Removal Reason | Migration Path |
|----------|----------------|----------------|
| `/api/v1/health` (simple) | Replaced by `/detailed` | Use `/api/v1/health/detailed` |
| `X-Tenant-ID` header support | ADR-028 ratified | Use `Authorization: Bearer` exclusively |
| `POST /api/v1/workflows/run` (sync mode) | Performance concern | Use async mode with polling |
| Inline agent config (`config` field) | ADR-016 deprecated | Reference config by ID from config store |

## Breaking Changes

### BC-1: AsyncLocalStorage Tenant Context (ADR-028)

**Before (v1.1):**
```python
# Explicit tenant_id passed through call chain
def process_document(document_id: str, tenant_id: str):
    tenant = get_tenant(tenant_id)
    # ... process
```

**After (v1.2):**
```python
# Tenant context from AsyncLocalStorage — no param needed
from core.context import tenant_context

def process_document(document_id: str):
    tenant = tenant_context.get_current_tenant()
    # ... process
```

**Migration:** Remove all `tenant_id` parameters from internal function signatures. The context is automatically set by middleware.

### BC-2: Tool Registry Schema-First (ADR-033)

**Before (v1.1):**
```python
from agents.tools import tool

@tool(name="extract_entities")
def extract_entities(text: str, tenant_id: str) -> list:
    """Extract entities from text."""
    return ner_model.extract(text)
```

**After (v1.2):**
```python
from pydantic import BaseModel
from agents.tools.registry import registry

class ExtractEntitiesInput(BaseModel):
    text: str

class ExtractEntitiesOutput(BaseModel):
    entities: list

@registry.register(
    name="extract_entities",
    input_schema=ExtractEntitiesInput,
    output_schema=ExtractEntitiesOutput,
    description="Extract entities from text.",
)
def extract_entities(input: ExtractEntitiesInput) -> ExtractEntitiesOutput:
    entities = ner_model.extract(input.text)
    return ExtractEntitiesOutput(entities=entities)
```

**Migration:** Use the migration script:
```bash
python scripts/migrations/v1.1-to-v1.2/migrate-tool-decorators.py
```

### BC-3: Agent Output Envelope (ADR-031)

**Before (v1.1):**
```json
{
  "result": {
    "insights": [...],
    "confidence": 0.95
  },
  "metadata": {
    "processing_time_ms": 1200
  }
}
```

**After (v1.2):**
```json
{
  "version": "1.0",
  "metadata": {
    "processing_time_ms": 1200,
    "agent_version": "2.1.0",
    "workflow_id": "wf_abc123"
  },
  "payload": {
    "insights": [...],
    "confidence": 0.95
  },
  "provenance": {
    "agent_id": "agent-insight-v2",
    "input_hash": "sha256:abc...",
    "tools_used": ["extract_entities", "summarize"],
    "started_at": "2026-07-14T10:00:00Z",
    "completed_at": "2026-07-14T10:01:12Z"
  }
}
```

**Migration:** Update consumers to read from `payload` instead of top-level fields. Access provenance via `provenance` key.

### BC-4: State Machine Route Validation (ADR-032)

**Before (v1.1):**
```typescript
// Direct navigation to any route allowed
router.push('/workflows/insight/results');
```

**After (v1.2):**
```typescript
// Navigation validated against state machine
// If workflow not completed, redirect to appropriate step
router.push('/workflows/insight/results');
// May redirect to /workflows/insight/configure if prerequisites not met
```

**Migration:** No code changes required. The state machine guards are automatic. Update E2E tests that relied on direct navigation to later wizard steps.

### BC-5: 8-Phase Auth Pipeline (ADR-029)

**Before (v1.1):**
```python
# Monolithic auth middleware
from middleware.auth import auth_middleware

app.add_middleware(auth_middleware)
```

**After (v1.2):**
```python
# 8-phase pipeline (registered automatically)
from middleware import AuthPipeline

app.add_middleware(AuthPipeline)
# Phases execute automatically: request_id → cors → rate_limit → 
#   token_extract → token_validate → tenant_resolve → permission_check → context_attach
```

**Migration:** Remove custom auth middleware. The pipeline is registered automatically. If you have custom auth logic, implement it as a pipeline phase.

## Step-by-Step Migration Checklist

### Phase 1: Preparation (30 minutes)

- [ ] **Read release notes** — `cat RELEASE_NOTES_v1.2.0.md`
- [ ] **Review breaking changes** — Confirm all BC items above are understood
- [ ] **Backup database** — `pg_dump fabric4l > fabric4l-v1.1-backup-$(date +%Y%m%d).sql`
- [ ] **Backup configuration** — `cp .env .env.v1.1-backup`
- [ ] **Run compatibility check** — `python scripts/migrations/v1.1-to-v1.2/check-compatibility.py`
- [ ] **Review contract compliance** — Visit `/api/v1/admin/contracts` and note any violations
- [ ] **Schedule maintenance window** — Estimated 10-15 minutes downtime

### Phase 2: Environment & Configuration (15 minutes)

- [ ] **Pull v1.2 code** — `git fetch origin && git checkout v1.2.0`
- [ ] **Install dependencies** — `pip install -r requirements.txt` (new packages added)
- [ ] **Update environment variables** (see table below)
- [ ] **Verify feature flag provider config** — Set `FEATURE_FLAG_PROVIDER` (launchdarkly, unleash, or config)
- [ ] **Configure GDPR settings** — Set `GDPR_DATA_CONTROLLER`, `GDPR_DPO_EMAIL`
- [ ] **Configure OTel exporter** — Set `OTEL_EXPORTER_OTLP_ENDPOINT` if using external collector

### Phase 3: Database Migration (10 minutes)

- [ ] **Run migrations** — `make migrate` or `alembic upgrade head`
- [ ] **Verify migration success** — `alembic current` should show latest revision
- [ ] **Seed feature flags** — `python scripts/seed-feature-flags.py`
- [ ] **Verify GDPR tables** — Confirm `gdpr_requests`, `consent_records` tables exist

### Phase 4: Code Migration (1-3 hours)

- [ ] **Remove tenant_id parameters** — Run `scripts/migrations/v1.1-to-v1.2/remove-tenant-params.py`
- [ ] **Migrate tool decorators** — Run `scripts/migrations/v1.1-to-v1.2/migrate-tool-decorators.py`
- [ ] **Update agent output consumers** — Change `result.key` to `result.payload.key`
- [ ] **Update health check calls** — Change `/health` to `/health/detailed`
- [ ] **Remove X-Tenant-ID usage** — Global find/replace in client code
- [ ] **Update workflow response handling** — Use `trace_id` for distributed tracing correlation

### Phase 5: Validation (30 minutes)

- [ ] **Run full test suite** — `make test`
- [ ] **Verify contract compliance** — All 6 contracts should show "Compliant"
- [ ] **Test feature flags** — Toggle a test flag via API
- [ ] **Test GDPR export** — Submit a test data export request
- [ ] **Verify OTel traces** — Check Jaeger/Tempo for traces
- [ ] **Run chaos experiment** — Execute a latency injection experiment
- [ ] **Check API docs** — Verify Scalar docs render at `/api/docs`

### Phase 6: Production Deployment (15 minutes)

- [ ] **Deploy to staging** — `make deploy-staging`
- [ ] **Run smoke tests** — `make smoke-test`
- [ ] **Deploy to production** — `make deploy-production`
- [ ] **Verify health** — `curl /api/v1/health/detailed | jq '.status'`
- [ ] **Monitor dashboards** — Watch error rates, latency, SLO compliance
- [ ] **Enable feature flags** — Gradually roll out new features

## Feature Flag Quick Start

### Checking Feature Flags

```python
from fabric4l import FabricClient

client = FabricClient(api_key="fab_ak_xxx")

# Check if feature is enabled
if client.features.is_enabled("new-extraction-engine", default=False):
    # Use new extraction engine
    pass
else:
    # Use legacy extraction engine
    pass

# Get feature flag value
variant = client.features.get_variant("insight-model-version", default="v1")
```

### Emergency Kill Switches

```bash
# Activate kill switch (immediately disables feature)
curl -X POST http://localhost:8001/api/v1/killswitches/new-extraction-engine/activate \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -d '{"reason": "Performance degradation detected", "timeout": 600}'

# Deactivate kill switch
curl -X POST http://localhost:8001/api/v1/killswitches/new-extraction-engine/deactivate \
  -H "Authorization: Bearer $ADMIN_TOKEN"

# List active kill switches
curl http://localhost:8001/api/v1/killswitches \
  -H "Authorization: Bearer $ADMIN_TOKEN" | jq '.[] | .key, .activated_at, .reason'
```

## GDPR Quick Start

### Data Export Request

```bash
# Initiate export
curl -X POST http://localhost:8001/api/v1/gdpr/data-export \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "subject_id": "user-123@example.com",
    "subject_type": "email",
    "format": "json"
  }'

# Check status (returns download URL when complete)
curl http://localhost:8001/api/v1/gdpr/data-export/exp_abc123 \
  -H "Authorization: Bearer $API_KEY" | jq '{status, download_url, expires_at}'
```

### Data Deletion Request

```bash
# Initiate deletion (right to erasure)

curl http://localhost:8001/api/v1/gdpr/data-deletion/del_abc123 \
```

## Troubleshooting

### "Contract violation detected" warning

**Cause:** Code doesn't conform to ratified ADRs.  
**Fix:** Run compliance checker and fix violations:
```bash
python scripts/check-contract-compliance.py --auto-fix
```

### Feature flags return 403

**Cause:** Feature flag provider not configured.  
**Fix:** Set `FEATURE_FLAG_PROVIDER` and `FEATURE_FLAG_SDK_KEY` environment variables.

### GDPR endpoints return 501 Not Implemented

**Cause:** GDPR module not enabled.  
**Fix:** Set `GDPR_ENABLED=true` and verify `GDPR_DATA_CONTROLLER` is set.

### OTel traces not appearing

**Cause:** OTel exporter endpoint not configured.  
**Fix:** Set `OTEL_EXPORTER_OTLP_ENDPOINT` to your collector URL.

### Tool registry fails at startup

**Cause:** Tools using old `@tool` decorator.  
**Fix:** Run migration script:
```bash
python scripts/migrations/v1.1-to-v1.2/migrate-tool-decorators.py
```

### State machine blocks valid navigation

**Cause:** Application state doesn't match expected state.  
**Fix:** Check state machine logs; clear browser localStorage if stale state exists.

## Post-Migration Verification Script

Save and run this comprehensive validation script:

```bash
#!/bin/bash
# scripts/validate-v1.2-migration.sh

set -euo pipefail

BASE_URL="${BASE_URL:-http://localhost:8001}"
ADMIN_TOKEN="${ADMIN_TOKEN:-}"
API_KEY="${API_KEY:-}"

echo "=== Fabric 4L v1.2 Migration Validation ==="
echo "Base URL: $BASE_URL"
echo ""

# 1. Health check
echo "1. Health check..."
curl -sf "$BASE_URL/api/v1/health/detailed" | jq '.status' || {
  echo "FAIL: Health check failed"
  exit 1
}
echo "   PASS"

# 2. Contract compliance
echo "2. Contract compliance..."
curl -sf "$BASE_URL/api/v1/admin/contracts" \
  -H "Authorization: Bearer $ADMIN_TOKEN" | jq '.contracts[] | select(.status != "Compliant")' | {

echo "   PASS"
```

# AI-Generated Dependency Change Review Policy

> **Status:** Active  
> **Owner:** Platform Security + SRE  
> **Effective date:** 2026-06-09  
> **Review cadence:** Quarterly  

## Purpose

This policy governs how AI-generated (including agent-assisted) changes to dependency manifests, lockfiles, and container base images are reviewed, tested, and merged. It applies to all package managers used in the Fabric 4L monorepo: pnpm (JavaScript/TypeScript), uv/pip (Python), and Docker.

## Scope

This policy covers changes to:
- `package.json` and `pnpm-lock.yaml`
- `pyproject.toml` and `uv.lock`
- `requirements.txt` and `poetry.lock`
- `Dockerfile` `FROM` lines and base image digests
- `dependabot.yml` and `.github/workflows/*` that affect dependency resolution
- Any script that modifies the above (e.g., `scripts/ci/supply_chain_gate.py`)

## Policy

### 1. AI-generated dependency changes require human review

- **No AI-generated dependency change may merge without at least one human reviewer** who is a CODEOWNER for the affected manifest.
- The PR body must include the `AI-Generated Change` checkbox (enforced by `.github/pull_request_template.md`).
- The reviewer must verify:
  - The change is intentional (not a hallucinated package name or version).
  - The package is from a trusted registry (npmjs.com, PyPI, Docker Hub official images, or an approved private registry).
  - The version constraint is appropriate (pinned in lockfiles, semantically constrained in manifests).

### 2. Lockfile integrity is non-negotiable

- AI agents must **never** hand-edit lockfiles (`pnpm-lock.yaml`, `uv.lock`, `poetry.lock`).
- Lockfiles must be regenerated by the canonical tool:
  - `pnpm install --frozen-lockfile` (root and `apps/web`)
  - `uv lock` (Python services)
- CI enforces lockfile freshness via:
  - `pnpm install --frozen-lockfile` fails on drift.
  - `uv sync --frozen --all-extras` fails on drift.

### 3. Automated gates must pass before merge

Every dependency-changing PR must pass:
- `validate-dependabot-coverage` (manifest ownership alignment)
- `supply_chain_gate.py audit` (lockfile presence, CI policy wiring)
- `pip-audit --severity high --exit-code 1` (Python services)
- `pnpm audit` or `npm audit` (frontend)
- Container base image pinning check (`FLOATING_IMAGE_RE` gate)

### 4. New dependencies require justification

If an AI agent introduces a **net-new** dependency (not a version bump):
- The PR description must explain why the existing dependency tree cannot satisfy the need.
- The reviewer must check the package's:
  - Maintenance status (last release < 12 months ago)
  - License compatibility (SPDX identifier must be in `docs/governance/approved-licenses.md`)
  - Security posture (no open CVEs scored HIGH or CRITICAL)

### 5. Exceptions

Time-boxed exceptions to this policy may be granted by `@value-fabric/security-leads` with:
- An explicit expiration date (max 30 days).
- A linked ticket in the exception register.
- A post-exception audit scheduled before expiration.

## Enforcement

- **CI gate:** The `structural-preflight` job in `.github/workflows/pr-checks.yml` runs `scripts/ci/check_pr_governance_fields.py`, which validates the `AI-Generated Change` checkbox.
- **CODEOWNERS:** All manifest files are owned by `@value-fabric/sre-leads`, ensuring SRE review on any dependency change.
- **Audit trail:** `artifacts/supply-chain/vulnerability-summary.json` is generated on every CI run and retained for 14 days.

## Rationale

Branch protection on `main` currently requires eight individual check contexts (`mandatory-security-regression`, `contract-compliance`, `Structural Preflight`, `prod-readiness`, `behavior-tests`, and three Layer 5 checks — confirmed live via `gh api .../branches/main/protection`). V1-CI-001 replaces this with nine stable aggregate checks (`01-repository-integrity` … `09-change-risk-and-approval`) that fan in over the existing job matrix, plus merge-queue support. The migration is staged so branch protection only changes after shadow parity is demonstrated.

## What the patch does (Stage 1 only)

- Adds nine aggregate jobs across six workflows. Aggregates do **no substantive testing** — they summarize existing child-job results via the new shared arbiter `scripts/ci/aggregate_gate.py`, failing closed on any child failure/cancel and on any skip that is not explicitly confirmed safe (change-scope output resolved false, or the job's event gate does not apply). `09-change-risk-and-approval` is the contract-mandated exception: deterministic policy (not LLM, not a summary) via new `scripts/ci/check_change_risk_approval.py` — schema-valid independent-review artifact, matching base/head SHAs, no unresolved P0/P1, CODEOWNER/human approval for high-risk surfaces, reviewer ≠ author.
- Adds `merge_group:` triggers to the six workflows that host required checks / future-required aggregates: `pr-checks.yml`, `security-gates.yml`, `contract-compliance.yml`, `prod-readiness.yml`, `supply-chain-integrity.yml`, `release-evidence-bundle.yml`.
- Registers the nine names as `informational_status_checks` in `docs/governance/branch-protection-required-checks.yml`; regenerates `workflow-registry.json` / `WORKFLOW_REGISTRY.md` / `docs/development/CI_GATES.md` (trigger columns only).
- Adds `tests/ci/test_aggregate_gates.py` (13 behavior tests: allowed, denied, and failure modes).

No required check is added, removed, renamed, or weakened. No thresholds change. Nothing is required that wasn't before.

## Expected gate behavior change

None at merge time. PRs additionally show nine informational `0x-*` checks. All should be green on healthy PRs except `09-change-risk-and-approval`, which fails until independent-review artifacts (`signoff-evidence/reviews/<head_sha>.json`) are produced — intended shadow behavior (design doc D-2). The eight existing required contexts are untouched.
